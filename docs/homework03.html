Activity 1: Weather (0.4 Points)¶

Michael is not amused by heat and humidity on campus and longs for the cool breeze of Fall. Obsessed with the weather, he compulsively checks weather.gov, which is a website by the National Weather Service. While checking the weather for the fifth time on his phone during class, he realized that he could actually apply some of the things he is learning in class to his current obsession.

For example, he realized that he can fetch the weather information for any zipcode, using the following URL:

$ curl -sL https://forecast.weather.gov/zipcity.php?inputstring=$ZIPCODE

For instance, the weather information for Notre Dame, Indiana can be retrieved using:

$ curl -sL https://forecast.weather.gov/zipcity.php?inputstring=46556

Looking at the data retrieved from the website, he notices that the forecast and temperature information is wrapped in [HTML] fields that contain the text "myforecast":

...
<p class="myforecast-current">Overcast</p>
<p class="myforecast-current-lrg">37&deg;F</p>
<p class="myforecast-current-sm">3&deg;C</p>
...

Michael wants to make a Python script weather.py that will fetch the weather information for any specified zipcode and extract the temperature and forecast. Unfortunately, despite taking AP Computer Science in high school, he is still a bit confused about using requests to fetch HTTP data and re to extract data using regular expressions.

You decide that you could use some practice with Python and regular expressions, and so you help him complete the weather.py script such that it behaves as follows:

# Display usage message
$ ./weather.py -h
Usage: weather [-c] ZIPCODE
    -c    Use Celsius degrees instead of Fahrenheit for temperature

If zipcode is not provided, then it defaults to 46556.

# Display temperature and forecast for default ZIPCODE (46556)
$ ./weather.py
Temperature: 78°F
Forecast:    Fair

# Display temperature and forecast for Orange, CA (92867)
$ ./weather.py 92867
Temperature: 69°F
Forecast:    NA

# Display temperature and forecast for Eau Claire, WI (54701) in Celsius
$ ./weather.py -c 54701
Temperature: 28°C
Forecast:    Fair

The weather.py script takes the following possible flags:

  • -c: This allows the user to specify that the temperature should be displayed in Celsius rather than Fahrenheit.

If the user specifies an unknown flag, then the program should print the usage message and exit with a failure status.

After the flags, the weather.py script accepts one positional argument as the ZIPCODE. If none is given, then 46556 is used by default.

Task 1: weather.py¶

To build this script, you will need to complete the weather.py Python script by implementing the following functions:

  1. weather(zipcode: int, url: str=WEATHER_URL, celsius: bool=False) -> tuple[Optional[str], Optional[str]]

    This function fetches the weather information for zipcode, extracts the temperature and forecast, and returns both. If celsius is True, then it returns the temperature in Celsius; otherwise, it returns the degrees in Fahrenheit.

    Hint: Use requests.get to fetch the data via HTTP and then use re.findall or re.search to extract the temperature and forecast information using regular expressions.

  2. main(arguments: list[str]=sys.argv[1:]) -> None

    This function processes the command-line arguments to determine whether or not the temperature should be in Celsius or Fahrenheit and which ZIPCODE to use (if none is specified then use 46556). Afterwards, it uses the weather function to retrieve the temperature and forecast information and then prints them both out.

    Hint: You can use the following format strings to print out the temperature and forecast:

    f'Temperature: {temperature}'
f'Forecast:    {forecast}'

Activity 2: Campus (0.4 Points)¶

It's been a while since Anna has been on campus. With so much construction in the last few years, it is difficult for even recent alumni to identify and locate all the buildings. Fortunately, Notre Dame Creative provides a Campus Map with an API that returns JSON data.

For example, accessing the following URL will give all the information about buildings named dillon:

# Fetch JSON data about "dillon"
$ curl -sL https://map.nd.edu/placemarks.json?q=dillon
[{"id":86,"name":"Dillon Hall","permanent_uid":"1030","geometry": ...]

As can been seen, this JSON object is quite large and complex... That said, the API is nice in that it allows users to query buildings by name or by tags such as tour or gameday.

Seeing the potential in helping alumni navigate campus, Anna wants your help in writing a campus.py script in Python that fetches this JSON data using requests and then outputs the results in a more simplified format.

Now that you have gotten some more practice with Python, you feel confident in your abilities to slice and dice data structures such as dicts and lists, so you decided to help Anna write the campus.py script with the following behavior:

# Display usage message
$ ./campus.py
Usage: campus [-n LIMIT -t TAGS] NAME
    -n LIMIT    Only display up to LIMIT results
    -t TAGS     Search for specified TAGS

You may either search by NAME or by TAGS, but not both at the same time.

# Search for buildings named cushing
$ ./campus.py cushing
   1. Cushing Hall of Engineering (125) [building,core]

      Opened in 1933, the exterior is embellished with the names of
      history's great scientists and engineers, as well as traditional
      engineering tools. The lobby includes intricate mosaics and a
      ceiling decorated with botanical and geometric forms.

# Search for buildings tagged as food and gameday
$ ./campus -t food,gameday
   1. Bond Hall (79) [tour,gameday,food,building,core]

      Built in 1917, Bond Hall was originally the university library.
      Besides its library, auditorium, computer lab and studio space,
      the hall’s main staircase serves as the platform for the Notre
      Dame Marching Band’s game-day concerts.

# Search for buildings named debartolo (limit results to 2)
$ ./campus -n 2 debartolo
   1. DeBartolo Hall (102) [tour,commencement,building,core]

      This is an all-purpose classroom building. When it was built in
      1992, it more than doubled Notre Dame’s classroom space with 84
      classrooms, lecture halls and auditoriums. Just inside the main
      entrance (the middle pavilion) is a statue of the Virgin Mary.
      It is the original version of "Our Lady of the Universe", carved
      by Rev. Anthony Lauck.

  2. DeBartolo Hall: East - North (588) [a11y,entrance_a11y,core]

      DeBartolo Hall accessible entrance East - North

The campus.py script takes the following possible flags:

  • -n: This allows the user to specify the maximum number of results to show (default is 5).

  • -t: This allows the user to specify a list of tags (ie. comma separated) to match rather than a name.

    Note: You should attempt to match all tags (ie. AND).

After the flags, the campus.py script accepts one positional argument as the NAME to search.

If the user does not specify a NAME or any TAGS, then the program should print the usage message and exit with a failure status.

Task 1: campus.py¶

To build this utility, you will need to complete the campus.py Python script by implementing the following functions:

  1. clean_description(html: str) -> str:

    This function cleans the html description by doing the following: removing images, removing links, replacing newlines with spaces, removing [HTML] tags, and stripping the final result.

    Hint: You may want to use multiple instances of re.sub and str.replace.

  2. campus(query: str, tags: list[str], limit: int=5) -> None

    This function uses the API provided by Campus Map to search for either buildings matching query or buildings matching all of the tags.

    It displays up to limit results in the following format:

    f'{index:4}. {placemark_name} ({placemark_id}) [{placemark_tags}]\n\n{placemark_description}'

    Hints: You can use str.join to combine the list of tags into a single string.

    Likewise, to have the description wrap nicely, you can use textwrap.wrap as follows:

    placemark_description = f'\n'.join(textwrap.wrap(
    clean_description(placemark['description']),
    initial_indent    = INDENT,
    subsequent_indent = INDENT,
))

    This uses textwrap.wrap to split the long description into a list of strings, and then recombines these indented strings back into a single description.

    To handle printing blank lines between entries (rather than after each entry), take a look at the approach used in the wikipedia.py example discussed in class.

  3. main(arguments: list[str]=sys.argv[1:]) -> None

    This function processes the command-line arguments to determine which NAME or TAGS to use to query the API of the Campus Map and then calls campus to output up to LIMIT results.

    Hint: You can use list.extend to add an entire list to the end of another list.
